# Decisions

One line per non-obvious choice, newest last.

- 2026-10-02: All packages live under `internal/`; devdash promises no public Go API.
- 2026-10-02: Module path `github.com/dogauzun/devdash`, pending the name check (DEV-20).
- 2026-10-02: macOS collector needs no cgo: libproc (`proc_pidinfo`, `proc_pidfdinfo`), `sysctl` and `mach_timebase_info` are resolved from libSystem with purego and called through `purego.SyscallN`, which also returns errno on darwin (EPERM vs ESRCH); no cgo fallback was needed (DEV-8, Risk 2).
- 2026-10-02: macOS process uid is the effective uid (`e_ucred.cr_uid`), as in ps's UID column; task CPU times are mach ticks converted with `mach_timebase_info` (125/3 on arm64); dual-stack listeners are reported as `tcp6 ::` (netstat prints `tcp46`) (DEV-8).
- 2026-10-02: XNU declares `xinpcb_n`, `xsocket_n` and `xtcpcb_n` under `#pragma pack(4)`, so naturally aligned offsets are wrong: `so_uid` 64, `so_last_pid` 68, `inp_vflag` 44, `inp_dependladdr` 64, `t_state` 36; checked against a recorded blob (`internal/collector/testdata/pcblist_n_listen.bin`) (DEV-10).
- 2026-10-02: macOS 27.0.1, no root: `net.inet.tcp.pcblist_n` (also `pcblist`, `pcblist64`) is served or withheld by process ancestry, not by the caller's own signature. With an ad-hoc-signed ancestor (`go run`, `go test`, and every child of ad-hoc devdash, including Apple-signed `netstat` and `sysctl`) it returns only the two `xinpgen` headers (count set, zero records, no error); ad-hoc devdash started from a shell under Apple/Developer-ID-signed parents gets the full list, and `so_last_pid` matched lsof for all 10 listeners (DEV-10, Risk 1).
- 2026-10-02: consequence: the opt-in `netstat -anv` fallback is useless when devdash is ad-hoc signed (netstat inherits the restriction and prints no sockets), and devdash under an ad-hoc parent (for example a Homebrew-built tmux; not tested, tmux not installed) will see an empty PCB list; empty stays "unknown" with a warning (DEV-10).
- 2026-10-02: macOS 27.0.1, no root, all 301 other-uid processes including launchd: `kern.procargs2` fails with EINVAL (not EPERM), `PROC_PIDTASKINFO`, `PROC_PIDVNODEPATHINFO` and `PROC_PIDLISTFDS` fail with EPERM; ps shows their RSS only because `/bin/ps` is setuid root (DEV-10, Risk 3).
- 2026-10-02: macOS snapshot p50 at ~900 processes (M1 Pro, macOS 27.0.1, `BenchmarkCollect` 3x200 runs): process table 0.29 ms (target 20), argv+cwd+task info 8.0 ms (target 20), listeners 1.5 ms incl. PCB list 0.09 ms (target 30), total 9.9 ms (target 75, budget 100); a single `devdash --json` run is 9–11 ms, so no mitigation is needed (DEV-11).
- 2026-10-02: macOS listener addresses are decoded from `inp_vflag`/`insi_vflag` in both the fd walk and the PCB list, not from `soi_family`: an AF_INET6 socket bound to `::ffff:127.0.0.1` (JVM default) is `tcp4 127.0.0.1` as in lsof, so one socket can no longer show up twice after the merge; a dual-stack `::` socket (netstat `tcp46`) is one `tcp6 ::` row (DEV-8 review).
- 2026-10-02: macOS rows are dropped when `proc_pidinfo` fails with ESRCH (process exited, or a zombie) and kept with fields marked unknown on EPERM (other uid), per the degraded-modes table; the `kern.procargs2` errno is not used for this because it is EINVAL in both cases (DEV-8 review).
- 2026-10-02: the opt-in `netstat -anv` fallback is removed from v1: netstat spawned by an ad-hoc-signed devdash inherits the PCB-list restriction and prints no sockets, so it cannot add anything; the fd walk is primary and an empty PCB list is "unknown" with a footer hint (DEV-10 review).
- 2026-10-02: Linux collector skips kernel threads by `PF_KTHREAD` in the stat flags and any process with an empty cmdline, so zombies are skipped too (DEV-9).
- 2026-10-02: Linux collector: any read error other than EACCES means the process exited and the row is dropped; EACCES on statm/cmdline/cwd marks the field unknown; without stat/status (hidepid) there is no row at all (DEV-9).
- 2026-10-02: Linux fd walk scans own-uid pids, or every pid when running as root; a listening socket shared after fork goes to the lowest pid holding it, usually the parent (DEV-9).
- 2026-10-02: Verified as uid 1000 against root processes (kernel 7.0.12-linuxkit, Docker Desktop VM): stat, status, cmdline and statm are readable, so pid/ppid/uid/name/start time, argv, CPU time and RSS are known; cwd, fd/ and environ fail with EACCES; root's listeners are visible in /proc/net/tcp with their uid but no owner pid. Spec table holds (DEV-10).
- 2026-10-02: hidepid=2 and hidepid=1 both hide other users' processes from uid 1000 (stat unreadable or dir absent), while /proc/net/tcp still lists their listeners with uid; since kernel 5.8 /proc/mounts prints them as `hidepid=invisible` / `hidepid=noaccess`, so detection warns on any hidepid value other than 0/off (DEV-10).
- 2026-10-02: Linux snapshot p50 with 505 processes (450 sleep, 50 nc listeners, 1 root listener forcing a full fd walk), measured in Docker Desktop's linuxkit VM on an arm64 Mac, not bare metal: proctable 9.7 ms (target 25), argv_cwd 3.8 ms (15), listeners 5.0 ms (15), total 18.7 ms (60, budget 100) (DEV-11).
- 2026-10-02: Same setup plus 20 processes holding 500 fds each (~12.7k fds): listeners 18.9 ms (target 15), total 34 ms; fd walk costs ~1.4 µs per fd, so it scales with own-uid fds, not processes. Within budget, so no optimisation yet; first mitigation if needed is to re-check last tick's (pid, fd) per inode before a full walk (DEV-11).
- 2026-10-02: Linux collector skips zombies by stat state `Z`/`X` and keeps user processes with an empty cmdline (Argv nil), so a process that blanks its argv still owns its listeners; supersedes the empty-cmdline skip above (DEV-9 review).
- 2026-10-02: Linux collector reads `btime` once per collector lifetime, because the kernel shifts it when the wall clock is stepped and every StartTime would jump for one tick (DEV-9 review).
- 2026-10-02: Linux collector reads each pid in one pass (stat, status, statm, cmdline, cwd) so a pid reused between passes cannot mix two processes; per-source timings are summed per pid (DEV-9 review).
- 2026-10-02: For Phase 1: a `/proc/[pid]/cmdline` read can block on the target's mmap_lock, and ctx is only checked between reads, so the engine must run `Collect` in a goroutine and stop waiting after the 1.5 s timeout (DEV-9 review).
- 2026-10-02: CI runs lint (GOOS=linux and darwin), the four cross-builds and tests in one `ubuntu-latest` job and only vet+test+bench on `macos-latest` (10x minutes); golangci-lint is pinned to v2.13.2 to match the local version (v2.14.0 is out; bump both together); later steps run after a failed one (`!cancelled()`) so a PR shows every failure in one run (DEV-19).
- 2026-10-02: Raw collector output lives in `model` (`model.Raw`, `model.RawListener`; raw processes are `model.Process` with only the collected fields set) and `collector` imports `model`, with `collector.Result`/`Process`/`Listener` as aliases. No conversion layer in the engine; `Build` makes the one copy per tick that keeps snapshots immutable. Collectors set `Unknown` bits, `TakenAt`, `Host` and `Warning{Code, Count, Hint}` directly (DEV-12).
- 2026-10-02: `model.Process` carries `CPUTime` (cumulative) besides `CPUPercent`, so the previous snapshot is the only state CPU percent needs (DEV-12).
- 2026-10-02: Unowned listeners get one PID 0 "unknown" process per distinct (proto, addr, port), not one shared row: reconciliation can then mark each as its own container, ports sort and filter per row, and SO_REUSEPORT duplicates collapse. A listener whose owner pid is not in the process list counts as unowned. Its row key adds the listener to (pid, start time) (DEV-12).
- 2026-10-02: `Build` adds one `listener_owner_unreadable` warning counting the PID 0 rows, as in the spec's JSON example; the interim `--json` prints NaN CPU percent as null until DEV-22 (DEV-12).
- 2026-10-02: The PID 0 "unknown owner" pseudo-process has kind `other`, as in the spec's JSON example, although it holds a listener (the kind table's `server` rule does not apply to it) (DEV-12 review).
- 2026-10-02: `kern.procargs2` layout, probed on macOS 27.0.1 with exec paths of every length mod 8, an empty argv[0] and empty middle and trailing arguments: argc, the exec path NUL-padded to a multiple of 8 from its start (XNU `exec_extract_strings`), then exactly argc strings. The decoder skips exactly that padding and reads argc strings; trailing empty strings are dropped and an all-empty (blanked) argv is nil, as Linux's cmdline gives. macOS 27 cuts the buffer after its own argv walk, which skips every NUL after the path, so with an empty argv[0] one environment string is still returned; it is never read (DEV-40).
- 2026-10-02: macOS drops an own-uid process whose `kern.procargs2` read fails. Under churn it fails only for processes that are exiting (EINVAL, then ESRCH), just forked or mid-exec (EIO), and 300 scans of ~590 live own-uid processes saw no other failure. argv is now read first. Other users' rows are unchanged. A live own-uid process whose argv could never be read would be hidden, with its listeners under PID 0; none was seen (DEV-41).
- 2026-10-02: macOS skips pid 0 (kernel_task); PID 0 is only the "unknown owner" pseudo-process (DEV-42).
- 2026-10-02: macOS listeners are deduplicated by socket handle (`soi_so` from the fd walk, `xso_so` from the PCB list: the same obfuscated pointer, checked on recorded blobs). A socket shared across fork goes to the lowest pid holding it. SO_REUSEPORT siblings stay distinct. The PCB list only adds handles the fd walk did not see (DEV-45).
- 2026-10-02: Darwin decoder blobs are `testdata/<source>.<case>.macos-<version>.<arch>.bin`, written by `DEVDASH_RECORD=1 go test -run TestRecordBlobs` from children with fixed argv, env and cwd and from the test's own sockets, so they hold no secrets. Every version's blobs must decode to the same values. Only macOS 27.0.1 arm64 is recorded; macOS 14 and 26 need a runner. `kinfo_proc` is decoded by `unix.SysctlKinfoProcSlice` and has no blob (DEV-14).
- 2026-10-02: Re-check of DEV-10 from a Claude Code shell on macOS 27.0.1: `go test`, `go run` (Homebrew go, ad-hoc signed) and a built devdash were all served the full PCB list. So the gate is not simply "any ad-hoc-signed ancestor", and live tests must not depend on whether the list is served. The warning hint still names the DEV-10 causes (DEV-14).
- 2026-10-02: Linux process uid is the effective uid (second field of the `Uid:` line in `/proc/[pid]/status`), compared with `os.Geteuid()`, as on macOS; spec said "real uid" and is updated (DEV-13).
- 2026-10-02: Linux fd walk stops once every listener whose socket uid (`/proc/net/tcp` column 8) is our euid is matched, all listeners as root; other users' sockets cannot be matched, so they no longer force a full walk. ponytail ceiling: a root-created socket held by an own-uid process (bind as root, then drop privileges) stays unowned when the walk stops before that pid (DEV-13).
- 2026-10-02: Linux fd walk keeps state between `Collect` calls: processes whose `fd/` gave EACCES, keyed by (pid, start time), and the sorted set of unmatched countable inodes. A walk skips those processes first and walks them only if the unmatched set then differs from last tick's. State is copied in and out under a mutex because a timed-out Collect may overlap the next (DEV-13).
- 2026-10-02: Linux collector sorts pids before reading, so the "lowest pid owns a fork-shared socket" rule does not rely on `/proc` readdir order (ascending in the kernel, arbitrary in a fixture dir); confirmed live against `ss -ltnp`, which lists both holders (DEV-45).
- 2026-10-02: Linux reports a v4-mapped `tcp6` listener (`::ffff:127.0.0.1`) as `tcp4 127.0.0.1` via `Addr.Unmap()`, matching macOS; a dual-stack `::` socket stays one `tcp6 ::` row (DEV-43).
- 2026-10-02: Linux strips the kernel's ` (deleted)` suffix from `readlink /proc/[pid]/cwd`, matching macOS's bare old path; a directory really named `x (deleted)` is stripped too (nlink 0 on a stat of cwd would tell them apart) (DEV-44).
- 2026-10-02: Fixture `internal/collector/testdata/proc-500` (515 pid dirs, 437 kept processes) is written by `proc500` in `collector_fixture_linux_test.go` with `go test ./internal/collector -run TestCollectFixture -update`, on Linux. Git cannot store modes, so tests copy it to a temp dir and chmod one process's cmdline, statm and fd/ to 000; root ignores that, so the expectations depend on the real euid (DEV-13).
- 2026-10-02: As root in a Docker container with default capabilities (no CAP_SYS_PTRACE), other users' `fd/` and `cwd` fail with EACCES like for a normal user, so their listeners stay unowned and the "run with sudo" hint is wrong there; `--cap-add SYS_PTRACE` restores full ownership (seen with `ss -ltnp` too) (DEV-13).
- 2026-10-02: `BenchmarkSnapshot` (collector + `model.Build`, 437 processes of the fixture, copied to a temp dir) is 10.4–11.2 ms/op in Docker Desktop's linuxkit VM on an arm64 Mac; reading the fixture straight from the macOS bind mount is ~20x slower, which is why the benchmark copies it (DEV-13).
- 2026-10-02: Kinds match the lower-cased basename of argv[0] with a login shell's leading `-` dropped (`-zsh`), or Name when argv is empty. Test subcommands (`go test`, `cargo test`, `bun test`) match argv[1] only; watcher flags (`tsc --watch`, `rollup -w`) match anywhere in argv; a basename ending in `.test` (a `go test` binary) is a test (DEV-17).
- 2026-10-02: Interpreter-wrapped tools: when argv[0] is an interpreter or package runner (node, nodejs, bun, bunx, npx, python, ruby; trailing version digits ignored, so python3.12), each kind rule is also tried on the tool it runs: the module after `-m`, else the basename of the first argument not starting with `-`, minus a .js/.cjs/.mjs/.ts/.py/.rb extension. So `node …/jest.js`, `python -m pytest` and `npx vitest` are tests and `node …/nodemon.js` a watcher; flags taking a separate value are not known (`node -r x app.js` yields x) (DEV-17).
- 2026-10-02: Tree: a process is a root when its ppid is 0 or 1, when its parent is in another group or is not a row, or when the parent did not start strictly before it by (start time, pid); the last rule detects a reused parent pid and makes ppid cycles impossible (DEV-17).
- 2026-10-02: "Processes with an empty argv are never rows" applies only to an argv known to be empty (`FieldArgv` not set) on a process with no listener. A process whose argv is unreadable (other uid) is always a row, per goal 6 and the degraded-modes table: it is classified and hidden by Name, and its children attach to it as usual (DEV-17 review).
- 2026-10-02: The default view never hides a process that owns a listener, even a shell or editor (`nvim --listen`, `gopls serve -listen`, a VS Code extension host running Live Server): it keeps its kind and is drawn normally, not dimmed, so every listening socket has a row (goal 1) (DEV-17 review).
- 2026-10-02: Groups: activity is the latest start time over all of a group's processes, hidden ones included, so `a` does not reorder groups; compose groups rank with project groups; ties go project before compose, then by key. A group with no row to show (only hidden processes with nothing visible below them) has no header either; a collapsed group keeps its header (DEV-17).
- 2026-10-02: A container with no process behind it is a row only when it publishes a host port (`HostPort != 0`); a container with only exposed ports shows nowhere in the table. Container-only rows have no start time, so the default "oldest first" puts them first among rows with ports (DEV-17).
- 2026-10-02: Filter: a query of digits only matches listener and published ports by prefix (`30` finds 3000), never names, argv or pids; any other query is a case-insensitive substring of process name or argv, container name or image, or a project or compose header name, and a matching header keeps its whole group (DEV-17).
- 2026-10-02: Project resolution stops at `$HOME` without checking it, so a repository rooted at `$HOME` never counts and nothing above `$HOME` is walked; with `--roots` the walk stops before the first directory outside every root without stat-ing it, so a cwd outside (or above) the roots costs no filesystem call and a hung mount there cannot block the refresh (DEV-16 review). `$HOME` and `--roots` are resolved through symlinks once in `NewResolver`, since collector cwds are the kernel's resolved paths (DEV-16).
- 2026-10-02: Resolver cache: only directories that found a repository are cached across ticks; a hit is one `lstat` of that repository's `HEAD`, valid only for the same inode, size and mtime (git renames `HEAD.lock` over it on every write, so the inode changes even where a coarse-mtime filesystem repeats the timestamp; DEV-16 review), not of `.git`, whose mtime changes on every index write. Directories with no project are memoised per tick only, so a new `git init` above them is seen next tick. At 4096 entries one arbitrary entry is evicted. Warm `BenchmarkResolve` (500 processes, 5 repositories, M1 Pro): 0.17 ms per tick, budget 5 ms; on this Mac's real 911 processes 1.1–1.8 ms warm (the uncached no-project walks dominate), 3.5 ms on the first tick (DEV-16).
- 2026-10-02: A `.git` file whose gitdir is `<common>/worktrees/<name>` is a linked worktree with `MainRepo` the work tree above `<common>` (or `<common>` itself for a bare repository); any other gitdir (submodule, `--separate-git-dir`) is its own project; a relative gitdir is joined to the `.git` file's directory; a `.git` file with no `gitdir:` line, or a symlinked `.git`/`HEAD`, is not a repository and the walk goes on. The argv fallback picks the innermost found project containing the path (DEV-16).
- 2026-10-02: Engine API: `New(Options)`, blocking `Run(ctx)` (shutdown is ctx cancellation; `Updates` is closed when Run returns), `Updates()` (size-1 channel, latest wins), non-blocking `Refresh()`, and a package-level one-shot `Snapshot(ctx, Options)` for the CLI that never starts the loop, so the loop's state has a single owner (DEV-18).
- 2026-10-02: Every tick publishes an `Update`, good or not: the last good snapshot, the tick's error, `Missed` (consecutive failed ticks) and the current interval; the TUI shows `stale N s` (N from `Snapshot.TakenAt`) when `Missed >= 2` (DEV-18).
- 2026-10-02: A tick that finds an abandoned `Collect` still running fails at once with an error wrapping `context.DeadlineExceeded` instead of waiting, counts as missed and as slow; the late result of the abandoned call is dropped as stale (DEV-18).
- 2026-10-02: Backoff: a tick is slow when collect+build takes over 500 ms or times out; three consecutive slow ticks double the interval (up to 10 s, never lowering a larger `--tick`), three consecutive fast ticks halve it, never below the configured interval. The next tick is scheduled one interval after the previous tick ends, so ticks never pile up (DEV-18).
- 2026-10-02: More than 5000 processes in the last good sample raises the interval floor to 5 s from the second tick on (the first tick is what counts them). Engine hints `refresh_slowed` and `many_processes` are appended to `Snapshot.Warnings`, so the footer and `--json` show them like collector warnings (DEV-18).
- 2026-10-02: The engine clamps `Tick` below 500 ms to 500 ms; rejecting it as a usage error is the CLI's job when `--tick` is added (DEV-18).
- 2026-10-02: No Docker hook in the engine yet: the tick passes `nil` containers to `Build`; DEV-27 adds the 5 s goroutine and a latest-list field (DEV-18).
- 2026-10-02: `Process.User` is filled by the engine after `Build`, not in `model`: `model` stays pure (no OS lookups) and the uid cache lives as long as the engine. Own uid via `os/user.Current()` (pure Go falls back to `$USER`, which covers macOS directory-service accounts), others via `os/user.LookupId` (`/etc/passwd` without cgo), the numeric uid on a miss; each uid is looked up once. The PID 0 pseudo-process keeps `User` "" (DEV-46).
- 2026-10-02: Name: `devdash` collides with `Phantas0s/devdash` (Go terminal dashboard, ~1,600 stars) and is taken on npm and PyPI, free on Homebrew core and crates.io; still open, the owner decides before the first tag; work continues under `github.com/dogauzun/devdash` (DEV-20).
- 2026-10-02: No `--system` flag: every listening TCP socket is shown (Goal 1); root-owned listeners below 1024 stay visible in the `other` group (DEV-20).
- 2026-10-02: Default refresh interval stays 2 s, with the adaptive backoff (DEV-20).
- 2026-10-02: UDP stays out of v1 (non-goal); planned for v1.1 (DEV-20).
- 2026-10-02: `port N` answers only for ports listening on the host, including published container ports; unpublished ports inside a Docker network are not reported (DEV-20).
- 2026-10-02: Correction to the DEV-46 line: without cgo, `os/user` on macOS is not the `/etc/passwd` reader; `Current` and `LookupId` call libSystem's `getpwuid_r` (`cgo_lookup_syscall.go`, tag `darwin`), which asks the directory service, so directory-service accounts resolve. The lookup can block on a hung network directory and runs in the `Run` goroutine outside the collection timeout; accepted for now (`ponytail:` comment on `lookupUser`) (DEV-46 review).
- 2026-10-02: Engine hints (`refresh_slowed`, `many_processes`) travel on `Update.Warnings`, computed every tick, not inside `Snapshot.Warnings`: backoff mostly starts on failed ticks, which publish the old snapshot, so hints in the snapshot never reached the footer. `Snapshot.Warnings` keeps only collector and `Build` warnings (DEV-18 review).
- 2026-10-02: A Linux process in the middle of exec (comm already the new program's, `/proc/[pid]/cmdline` zero bytes because the kernel sets the argv range in `create_elf_tables`, after the CLOEXEC status pipe that `cmd.Start` waits on is closed) is reported as it is: present, new Name, Argv nil; the next tick shows its argv. ps cannot tell this apart either (it prints `[comm]`), and marking argv unknown would raise the "run with sudo" warning for one tick; pinned by fixture pid 1148 (DEV-47).
- 2026-10-02: The live test's child is `cat`, and the test waits for it to echo a line before collecting: that proves exec finished and argv is published, without sleeping. `sleep` asserted right after `Start` failed 14/1000 runs with a slow-loading binary (DEV-47).
- 2026-10-02: Correction to the DEV-14 PCB re-check line: it was wrong. A withheld `net.inet.tcp.pcblist_n` is not header-only. It still holds the caller's own sockets, and I read the test's own listeners in it as "served". Re-checked from the same shell: `go test` and `go run` are withheld (0 PCBs of other processes, `pcblist_unavailable`), and a built devdash started from the shell is served, as DEV-10 found. The collector now treats a list with no PCB of another pid as withheld (DEV-14 review).
- 2026-10-02: Exception to the DEV-41 drop rule: when `kern.procargs2` fills the whole `kern.argmax` buffer, the strings area (exec path twice, argv, env, apple strings) was larger and the kernel returned its tail, so argc no longer lines up. The row is kept with argv unknown instead of decoding env or garbage as argv. This was reproduced with a 690-byte exec path and a ~1,048,000-byte argument, and a larger buffer does not help (DEV-40 review).
- 2026-10-02: Kill API is two steps: `NewPlan(snapshot, RowKey, KillOptions)` returns the exact ordered `Plan` or a `*Refusal`, and `Kill(plan, timeout)` (or `(*Engine).Kill`, which then calls `Refresh`) signals only what is in it. Force is orthogonal to tree: it turns SIGTERM into SIGKILL for whichever set was chosen, as the CLI's independent `--tree`/`--force` flags imply (DEV-24).
- 2026-10-02: Tree kill of a process-group leader sends one `kill(-pgid)` in place of the leader's own signal: the kernel delivers it to the whole group in one pass, so no member is signalled before the supervisor. Descendants outside the group follow one by one, breadth first. Group members the snapshot shows (by `getpgid` at plan time) are listed after the descendants. Process mode never signals the group. A group holding devdash, its parent or any ancestor refuses the action (DEV-24).
- 2026-10-02: Each pid's start time is re-read just before `kill(2)` (`kern.proc.pid` on macOS; `/proc/[pid]/stat` field 22 on Linux, with `btime` read once at package init like the collector's). A different start time is `ErrStartTime` ("not signalled"), not "exited", so a stepped Linux clock can never yield a false exit code 0. An unreaped zombie counts as gone (macOS `p_stat == SZOMB`, Linux state `Z`/`X`). Exit codes: 3 if any pid gave EPERM, else 4 if anything planned still runs or was not signalled, else 0 (DEV-24).
- 2026-10-02: Refusals cover the whole set: a container port anywhere in the tree refuses it (hint `docker stop <name>`, or the ID when Docker gave no name). devdash's ancestors are its parent from `os.Getppid()` and then the snapshot's ppid chain, which stops at the first ancestor missing from the snapshot (DEV-24).
- 2026-10-02: The group signal is sent only when every planned member still in the target's group re-validates. If one is reused or its start time is unreadable, `-pgid` would reach it too, so the leader is signalled alone and the validated rest one by one, parent first; the failed member is reported "not signalled". A failed member that has left the group does not block the group signal (DEV-24 review).
- 2026-10-02: devdash's ancestor chain is also read fresh from the OS (parent, then each one's parent via `kern.proc.pid` / `/proc/[pid]/stat`, up to pid 1 or a read error). `NewPlan` refuses that chain as well as the snapshot's, and `Kill` refuses, with nothing signalled, a plan naming any pid of it or a group holding any of them. This supersedes the "chain stops at the first ancestor missing from the snapshot" gap above (DEV-24 review).
- 2026-10-02: `Process.Name` is the basename of argv[0] (a login shell's leading `-` dropped, as in `Classify`) only when the kernel name is at least 15 bytes (Linux keeps 15 of comm, macOS 16 of p_comm) and a strict prefix of that basename, which is exactly the truncation case; otherwise the kernel name stays, so a rewritten title (`nginx: master process …`, `postgres: checkpointer`), a symlinked argv[0] (`python3` for `python3.12`) or an unrelated argv[0] never invents a name. Done once in `model.Build` for both OSes. On this Mac 1 of 897 processes keeps a cut name (`1Password Browse`, argv[0] unrelated) (DEV-48).
- 2026-10-02: CLI flags may come before or after the subcommand: `parse` resumes the stdlib `flag` parser after each positional argument, so no subcommand can take an argument starting with `-` (`port -1` is a flag error, still exit 2). `--roots` is comma-separated and repeatable, relative paths are made absolute, and a path containing a comma cannot be given (DEV-21). A leading `~` or `~/` is expanded to `$HOME` by devdash, because the shell does not expand it after a comma or `=` (`--roots ~/code,~/work`, `--roots=~/code`); `~user` is a usage error, and so is a root that does not exist or is not a directory, naming the path, instead of silently matching no project (PR #11 review).
